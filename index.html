Outlining steps to publish a site with GitHub Pages. Outlining steps to publish a site with GitHub Pages. Here are the GitHub Pages steps. GitHub’s layout changes now and then, so follow the on-screen labels if they differ slightly from mine. Set up Go to github.com and sign in, or create a free account. Click the + in the top right and choose New repository. Name it something like dirty-soda-club. Set it to Public, since free Pages needs that. Tick Add a README file so the repo isn’t empty, then click Create repository. Upload the file Make sure your file is renamed to index.html. On the repository page, click Add file → Upload files. Drag index.html into the box, wait for it to finish, then click Commit changes. Turn on Pages Click the Settings tab at the top of the repository. In the left sidebar, click Pages. Under Build and deployment, set Source to Deploy from a branch. Under Branch, choose main and the / (root) folder, then click Save. Get your link Wait one to two minutes, then refresh the Pages settings. A box appears saying your site is live, with the address. The link looks like https://yourusername.github.io/dirty-soda-club/. Open it on your computer and your phone, and test the drink builder. Things to know Your GitHub username will be in the link. If this is for their business, consider making a free account named after the business, like thedirtysodaclub, and hosting it there. Their link then becomes thedirtysodaclub.github.io/... and looks more professional. It also lets them own it later. Updating the page later: open index.html in the repository, click the pencil icon to edit, make your change, and commit. The live page updates in a minute or two. If you get a 404: the file isn’t named exactly index.html, it was uploaded into a subfolder, or Pages hasn’t finished building. Check the file name first, then wait a couple of minutes. Once it’s live, use that link in your message to them. If anything fails, tell me which step you’re stuck on and what you see.
